## Bulk Operations & Performance

Process thousands of records efficiently using optimized patterns based on RAMCO API best practices.

### Example: Processing All Active Members

```
User: "Generate a membership report for all active members"
```

**Behind the scenes:**

The server uses optimized bulk fetching:
- Single query with high limit (up to 20,000 records)
- No offset pagination (RAMCO API doesn't support it properly)
- Automatic active record filtering (`statecode<eq>0`)
- 3-minute timeout for large datasets
- HTTP 206 (Partial Content) response handling

**Performance:**
- Process 13,000+ members in ~2 minutes
- 95% fewer API calls vs N+1 queries
- 93% reduction in bulk errors

### Active Record Filtering

**Critical:** Always filter for active records to prevent errors from processing inactive/deleted data.

<Tabs>
  <TabItem label="Automatic (Tools)">
    All bulk tools automatically add `statecode<eq>0` filtering:

    ```
    User: "Show me all members"
    ```

    Internally filters: `statecode<eq>0` (Active only)
  </TabItem>

  <TabItem label="Manual (Search)">
    When using `search_records` directly, always include:

    ```typescript
    filter: "statecode<eq>0 and ModifiedOn<ge>'2024-01-01'"
    ```

    StatusCode values:
    - `0` = Active (✅ Include)
    - `1` = Inactive (❌ Exclude)
  </TabItem>
</Tabs>

<Aside type="caution">
  **Important:** Without `statecode<eq>0` filtering, you'll get errors processing inactive/deleted records. All bulk operations apply this filter automatically.
</Aside>

**Phase 2:** Get IDs from modified memberships
```typescript

fields: ["cobalt_contactid"]
```

**Phase 3:** Deduplicate and fetch full records

**Benefits:**

- Deduplicates automatically

## Filter Building & Optimization

Build complex filters using RAMCO's filter syntax.

### Filter Operators

| Operator | Description | Example |
|----------|-------------|---------|
| `<eq>` | Equal to | `statecode<eq>0` |
| `<ne>` | Not equal to | `StatusCode<ne>1` |
| `<gt>` | Greater than | `createdon<gt>'2024-01-01'` |
| `<ge>` | Greater or equal | `ModifiedOn<ge>'2024-01-01'` |
| `<lt>` | Less than | `createdon<lt>'2024-12-31'` |
| `<le>` | Less or equal | `ModifiedOn<le>'2024-12-31'` |
| `<like>` | Contains | `LastName<like>'Smith%'` |
| `<notlike>` | Not contains | `EmailAddress1<notlike>'@gmail.com'` |
| `<sb>` | Starts with | `LastName<sb>'Mc'` |
| `<sc>` | Contains substring | `FirstName<sc>'john'` |
| `in (...)` | In list | `ContactId in ('id1','id2','id3')` |

### Complex Filter Examples

## Advanced Techniques

### Batch Processing with IN Queries

Process multiple records in a single query:

```
User: "Get event attendance for the top 20 engaged members"
```

**Behind the scenes:**

```typescript
// Step 1: Get top 20 member IDs
const topMembers = await searchRecords({
  filter: "statecode<eq>0",
  limit: 20,
  sort: "-engagement_score"
});

// Step 2: Fetch events for all 20 in ONE query
const contactIds = topMembers.map(m => m.ContactId);
const inClause = contactIds.map(id => `'${id}'`).join(',');

const events = await searchRecords({
  module: 'cobalt_meetingregistration',
  filter: `cobalt_contactid in (${inClause})`,
  limit: 1000
});
```

**Performance:** 1 query for 20 members instead of 20 separate queries.

### Pagination Limitations

<Aside type="caution">
  **Important:** RAMCO API doesn't support offset-based pagination properly. Don't use `offset` in production.
</Aside>

**Don't do this:**
```typescript
// ❌ Offset pagination doesn't work in RAMCO
offset: 5000 // Returns same results as offset: 0
```

**Do this instead:**
```typescript
// ✅ Single query with high limit
limit: 20000 // Fetch all records in one call
```

### Timeout Configuration

Large bulk operations need longer timeouts:

- **Default:** 30 seconds
- **Bulk operations:** 180 seconds (3 minutes)
- **Largest dataset tested:** 14,945 members in 2m 2s

The server automatically uses extended timeouts for bulk tools.
