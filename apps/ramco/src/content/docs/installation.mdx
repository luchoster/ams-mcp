## Prerequisites

Before you begin, make sure you have:

- **RAMCO API Key** - Contact your RAMCO administrator to obtain access credentials
- **A Claude client** - Claude Code CLI, Claude Desktop, or claude.ai
- **Association GUID** (optional but recommended) - Your RAMCO association identifier

<Aside type="tip">
  **New to MCP?** The Model Context Protocol allows AI assistants like Claude to connect to external data sources. RAMCO MCP Server is a **remote** MCP server: nothing is installed on your computer, you only point Claude at `https://ramco.amsmcp.dev/http` and give it your API key.
</Aside>

## Choose Your Client

The setup differs by client. Pick the tab that matches what you use.

<Tabs>
  <TabItem label="Claude Code CLI">
    Claude Code connects to remote HTTP servers directly and can send custom headers, so this is the simplest setup.

    ```bash
    # Single association (recommended)
    claude mcp add ramco https://ramco.amsmcp.dev/http -t http \
      -H "Key: your-ramco-api-key-here" \
      -H "ramco-association-id: your-association-guid-here"

    # All associations
    claude mcp add ramco https://ramco.amsmcp.dev/http -t http \
      -H "Key: your-ramco-api-key-here"
    ```

    Or add it to a project `.mcp.json` file:

    ```json title=".mcp.json"
    {
      "mcpServers": {
        "ramco": {
          "type": "http",
          "url": "https://ramco.amsmcp.dev/http",
          "headers": {
            "Key": "your-ramco-api-key-here",
            "ramco-association-id": "your-association-guid-here"
          }
        }
      }
    }
    ```

    Restart Claude Code (or run `/mcp`) and ask: *"Tell me about my association"*.
  </TabItem>

  <TabItem label="Claude Desktop / claude.ai (Connector)">
    Claude Desktop and claude.ai use **custom connectors** for remote MCP servers. Requests come from Anthropic's cloud, so this works on every device where you are signed in, including the mobile apps.

    <Steps>

    1. ### Open Connectors

       Go to **Customize > Connectors** (on Team/Enterprise plans an Owner does this under **Organization settings > Connectors**).

    2. ### Add a custom connector

       Click **Add**, then **Add custom connector**.

    3. ### Enter the name and URL

       - **Name:** `RAMCO`
       - **MCP server URL:** `https://ramco.amsmcp.dev/http?association=your-association-guid-here`

       The `?association=` query parameter filters every query to that association. Leave it off to access all associations.

    4. ### Choose authentication

       Click **Next**. Under **Authentication** leave **No sign-in** selected (RAMCO uses API keys, not OAuth; Claude shows it as *Detected*).

       Under **Request headers** click **Add header**, pick the name from the dropdown and paste the value:

       | Header name | Value |
       | - | - |
       | `x-api-key` | `your-ramco-api-key-here` |

       Leave **Required** checked. If `x-api-key` is not offered, use `authorization` with the value `Bearer your-ramco-api-key-here` (include the word `Bearer` and the space).

    5. ### Save and test

       Click **Add**, then ask Claude: *"Tell me about my association"*.

    </Steps>

    <Aside type="caution">
      **The header name must come from the dropdown.** Claude only forwards a fixed list of approved header names. A typed name such as `x-key` or `ramco-key` is silently dropped, the server never receives the key, and Claude reports that the connector *needs you to sign in again*. Use `x-api-key` or `authorization`.
    </Aside>

    <Aside type="caution">
      **Request headers is in beta.** If the dialog has no **Request headers** section after clicking **Next**, your Claude organization does not have it yet. Use the **mcp-remote** tab instead.
    </Aside>

    <Aside>
      The association GUID goes in the **URL**, not a header, because connector headers are limited to a fixed list of approved names. `authorization` and `x-api-key` are both accepted by this server; `ramco-association-id` is not an approved connector header name.
    </Aside>
  </TabItem>

  <TabItem label="Claude Desktop (mcp-remote)">
    Claude Desktop's `claude_desktop_config.json` file only launches **local** servers; it ignores `url` and `headers` entries. The `mcp-remote` package bridges the gap by running a small local process that forwards to the remote server with your headers. Requires [Node.js](https://nodejs.org) 18 or newer.

    <Steps>

    1. ### Locate the config file

       **macOS:**
       ```bash
       ~/Library/Application Support/Claude/claude_desktop_config.json
       ```

       **Windows:**
       ```bash
       %APPDATA%\Claude\claude_desktop_config.json
       ```

    2. ### Add the bridge

       ```json title="claude_desktop_config.json"
       {
         "mcpServers": {
           "ramco": {
             "command": "npx",
             "args": [
               "-y", "mcp-remote", "https://ramco.amsmcp.dev/http",
               "--header", "Key:${RAMCO_API_KEY}",
               "--header", "ramco-association-id:${RAMCO_ASSOCIATION_ID}"
             ],
             "env": {
               "RAMCO_API_KEY": "your-ramco-api-key-here",
               "RAMCO_ASSOCIATION_ID": "your-association-guid-here"
             }
           }
         }
       }
       ```

       To access all associations, remove the second `--header` pair and the `RAMCO_ASSOCIATION_ID` entry.

       The `${VAR}` form keeps spaces out of the arguments, which avoids a known `mcp-remote` argument-parsing problem on Windows.

    3. ### Restart Claude Desktop

       Completely quit and reopen Claude Desktop. The first start downloads `mcp-remote` and may take a few seconds.

    4. ### Verify

       Ask Claude: *"Tell me about my association"*.

    </Steps>

    <Aside>
      **Windows:** if `npx` is not found, replace `"command": "npx"` with the full path, for example `"C:\\Program Files\\nodejs\\npx.cmd"`.
    </Aside>
  </TabItem>
</Tabs>

## Local Development

To test changes to the MCP server itself, run it locally on port 3001 and point Claude Code at it:

```bash
claude mcp add ramco-local http://localhost:3001/http -t http \
  -H "Key: your-ramco-api-key-here" \
  -H "ramco-association-id: your-association-guid-here"
```

Custom connectors cannot reach `localhost`; use Claude Code or the `mcp-remote` bridge for local testing.

## Finding Your Association GUID

To find your association GUID:

<Steps>

1. ### Use the authenticate Tool

   After configuring with just your API key (without association ID), ask Claude:
   ```
   "Test my RAMCO connection"
   ```

2. ### Review the Response

   The `authenticate` tool will return a list of all accessible associations with their GUIDs:
   ```json
   {
     "ramco_associationid": "965ef164-xxxx-xxxx-xxxx-xxxxxxxxxxxx",
     "ramco_name": "Your Association Name"
   }
   ```

3. ### Copy the GUID

   Copy the `ramco_associationid` value and add it to your configuration: the `ramco-association-id` header (Claude Code, mcp-remote) or the `?association=` URL parameter (custom connector).

</Steps>

<Aside>
  **Multiple Associations?** If you have access to multiple associations, you'll see all of them in the authenticate response. Choose the one you want to work with primarily.
</Aside>

## Testing Your Connection

Once installed, test your connection with these commands:

### Basic Connection Test
```
"Test my RAMCO connection"
```
Uses the `authenticate` tool to verify API credentials.

### Get Association Info
```
"Tell me about my association"
```
Uses the `get_association_info` tool to retrieve association details.

### Quick Analytics
```
"Give me a membership health check"
```
Uses the `analyze_membership_health` tool to analyze your entire membership.

## Troubleshooting

### Claude doesn't recognize RAMCO tools

**Solution:** Make sure you've completely quit and restarted Claude Desktop after modifying the config file. In Claude Code, run `/mcp` to check the server status.

### Claude Desktop ignores my config

**Solution:** `claude_desktop_config.json` does not support `"url"` / `"headers"` entries; those only work in Claude Code. Use the custom connector or the `mcp-remote` bridge described above.

### "API key is required" error

**Solution:** Double-check the key is entered correctly. In a custom connector the header must be `x-api-key` with just the key, or `authorization` with the value `Bearer your-key` (including the word `Bearer` and a space).

### Custom connector says it "needs you to sign in again"

**Solution:** The API key is not reaching the server. Claude turns the server's *missing key* response into a sign-in prompt. The usual cause is a header name that is not on Claude's approved list (for example `x-key`); only names chosen from the dropdown are forwarded. Remove the connector, add it again, and pick `x-api-key` or `authorization` from the dropdown. Header settings cannot be edited on an existing connector.

### Custom connector shows "Couldn't reach" or "Connect"

**Solution:** The URL must be exactly `https://ramco.amsmcp.dev/http` (optionally followed by `?association=...`). Choose **No sign-in**; this server does not support OAuth.

### "Association not found" error

**Solution:** Verify your association GUID is correct. Try running authenticate without the association ID first to see available associations.

### Connection timeout

**Solution:**
- Verify you have internet connectivity
- Check that the URL is correct (https://ramco.amsmcp.dev/http)
- Try the SSE transport as an alternative

### Tools return empty results

**Solution:**
- Verify your API key has proper permissions in RAMCO
- Check that your association has the data you're querying
- Ensure the entity types you're querying exist in your RAMCO instance

<Aside type="caution">
  **Security Note:** Your API key is transmitted via HTTPS and exists in memory only during request processing. The RAMCO MCP Server does not store, log, or retain API keys. See our [Privacy Policy](/privacy-policy) for details.
</Aside>
